# EC2 続き　
## OSを管理者権限で操作できる
- 起動したec2インスタンスでは、AWS symple managerのセッションマネージャーやsshを使用してosを管理者権限で操作できる。
  - sshとは自分のpcからec2サーバーに安全にアクセスするためのもので鍵を持つ。また、そこからターミナルで操作していく。
  - セッションマネージャーとはAWS symple managerの中の機能の一つでsshを使用しなくてもec2サーバーにアクセスできる
### セッションマネージャー
AWSsymplemanagerの機能の一つ。三つの前提条件のもとで使用できる。
- 使用条件
  - SSMAgentがOSにインストールされている。
    - SSMAgentはほとんどのクイックスタートAMIに入っている。
    - SSM Agent = EC2とAWS管理サービスをつなぐ橋でEC2の中で動く小さなプログラム

  - EC2インスタンスがsystemmanagerで管理できるようにIAMロールを引き受けている
  - EC2インスタンスからのリクエスト送信がSystemMnagerのエンドポイントに到達できる
- OSに安全に接続できて、管理者権限で操作できる。

## ELB の概要
- Elastic load Balancig
- Desin for FailureのアンチパターンでEC２インスタンスを複数のアベイラビリティーゾーンに配置してユーザーから単一アクセスを受け付けるようにする

### EC2インスタンスの可用性、耐障害性を高めるためにELBを使う
## ELBの特徴
- ロードバランサータイプ
- ヘルスチェック
- インターネット向け/内部向け
- 高可用性マネージドサービス
- クロスゾーン負荷分散
  ## ロードバランサータイプ
  - ELBには4つのタイプがある＊ここでは２つ
    - application Load Balancer: httpまたはhttpsのリクエストを負荷分散する用途で選択。webappicationに対して高度な機能が提供される
    - network Load Balancer:Http,Https以外の時に選択する
    - ALBにない機能は性的なipアドレスを使用できる。1秒あたり数百万のリクエストを処理できる
  ### http/httpsではALBそれ以外ではNLBを使う

## 3/23
 ## ヘルスチェック
 - ELBはインスタンスが正常かどうかヘルスチェックする
 - パスへの接続試行で状態を確認する
 ## インターネット向け/内部向け
 - ELBは外部内部どっちかを選択する
 ### インターネット向けELB
 - パブリックipアドレスが付与され外部からインターネット接続できる。
 ### 内部向けELB
 - DNSにプライベートipアドレスが付与され外部からは受け付けず内部での接続を許可する

 ###  インターネット向けだけでなく内部もELBを挟むことによってシステムの可用性をさらに高められる。
 ## 高可用性のマネージドサービス
 - ELBを使うことでEC2の高可用性を実現できる、よってELBは単一障害点ではないのか？
   ### 違う
   - ELB自体が高い可用性を持ったマネージドサービス
   - ユーザからのリクエストが増えればその分ELBのノードも増えて対応する
